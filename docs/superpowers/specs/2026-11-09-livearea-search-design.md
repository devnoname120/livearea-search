# LiveArea Search Design

> Result-page geometry and empty-query behavior are superseded by [Full-Screen Search and Persistent Recents](2026-11-10-fullscreen-search-and-recents-design.md). The remaining architecture and lifecycle requirements continue to apply.

## Goal

Add a SceShell user plugin which exposes a native ScePaf search control only on the bubble Home LiveArea. Pressing it opens the Vita IME; matching installed applications update progressively in a Vita-native vertical list as text changes. Selecting a row opens that title's LiveArea through the same URI route used by SceShell.

## Scope

The first release searches installed AppDB titles by localized display title, application name, title ID, and category. It does not index files, PSN catalog data, or content not registered in SceLsdb. The overlay is deliberately independent of Sony's private widget trees: it uses a plugin-owned PAF page and only relies on stable module exports and public PAF widget behavior.

## Architecture

### Portable search core

`AppIndex` owns copied application metadata and performs query normalization, token matching, deterministic ranking, and result limiting. It has no Vita or ScePaf dependency and is covered by host tests.

Ranking order is:

1. exact normalized display-title or title-ID match;
2. display-title or title-ID prefix match;
3. token-prefix match;
4. substring match;
5. application-name/category-only match.

Ties are resolved by display title and then title ID, making output stable across AppDB enumeration order.

### AppDB adapter

The shell process already owns the process-global SceLsdb connection. The adapter creates only the lightweight `SceLsdbAppDatabase` token, enumerates `sceLsdbGetAllAppInfo`, copies borrowed strings during the callback, and ends the token immediately. It never retains an AppInfo object or a pointer returned by an AppInfo getter.

The adapter resolves SceLsdb exports by module/library/function NID at runtime. This avoids requiring unreleased SceLsdb import stubs and keeps the source usable with a normal VitaSDK plus ScePaf-RE installation.

### ScePaf overlay

A resource-backed PAF plugin owns two pages:

- a non-modal lower-right Search control containing a native `corner_button` whose common background, highlight, glow, sound, and geometry are retained while its stock ellipsis is replaced by a magnifying-glass texture;
- a modal result surface containing a header, a vertical `ListView`, an empty-state label, and a native bottom-left close control.

The Home control accepts front-touch input but disables focus, keycode, and analog events so it cannot consume controller navigation. The search action focuses a PAF `TextBox`; the overlay reads its text on each PAF frame and updates the result set whenever the normalized query changes. While editing, a compact dark surface presents results only in the region above the system keyboard. Enter ends editing and restores the full result surface without re-running an unchanged query. If PAF starts editing internally after the submitted search field is tapped, the frame policy adopts that native edit and returns to the compact layout.

The results list uses `ListView::LAYOUT_TYPE_LIST`, one segment, fixed 70 px cells, 64 px application artwork, and normal 960 x 544 coordinates. It relies on ListView's native virtualization, kinetic scrolling, focus behavior, and scaling rather than a custom transform. The full dark surface covers the complete screen so overscroll cannot expose shell blue beneath rows; the compact surface spans from the header to the keyboard boundary. Rows contain one artwork tile and one primary title line, with no title-ID metadata.

Rows are generated by a `listview::ItemFactory`. Each row is a PAF `ListItem` containing an `app_icon_simple` artwork widget and a PAF title widget. Artwork loading is asynchronous and generation-safe: a reused row may only accept the texture belonging to its current title ID. Visible rows pin their surfaces. If the native surface pool rejects a new load, the cache selects the least-recently-used unpinned surface whose only reference is the cache, releases it, and retries. The persistent entry retains its key and path so it can reload when revisited. A missing source file is detected before eviction and remains a neutral placeholder.

### Launching

A selected row is converted to `psgm:open?titleid=<TITLE_ID>` and passed to `sceAppMgrLaunchAppByUri(0x20000, uri)`. This asks SceShell to open the title's normal LiveArea/application launcher instead of invoking a private launcher vtable or directly starting the executable.

### Shell lifecycle

A resident worker waits until SceShell's PAF module is present, validates AppMgr foreground state, and registers a PAF-main-thread callback that loads the resource plugin exactly once. The UI controller tracks plugin/page lifetime and performs idempotent page teardown. Visibility is gated by AppMgr foreground ownership plus the verified topmenu Home page and horizontal ScrollView focus/target. The control is therefore hidden on title LiveAreas, PlayStation Store, other system PAF pages, transitions away from Home, and while the result page is open.

## Failure handling

- Missing RCO or magnifier texture: log the exact failure and decline residency. Unresolved mandatory exports unload the PAF resource plugin without installing a partial UI.
- AppDB enumeration failure: show a native empty/error state and preserve the search button.
- Empty-query behavior is defined by the approved full-screen/Recent follow-up design.
- No matches: show the result page with a localized empty-state message.
- Launch failure: leave the list open and log the error code.
- App icon source missing: retain the neutral placeholder without evicting another icon.
- Surface-pool pressure: evict only an unpinned cache-owned LRU surface and retry; if no eligible surface exists, retain the placeholder and retry when the row is revisited.
- Allocation failure: stop the current operation without retaining borrowed AppDB pointers.

## Build and deployment

The repository provides:

- a host CMake target for the portable core and tests;
- a Vita CMake target when `VITASDK` and ScePaf-RE headers/libraries are available;
- RCO XML and generated hash constants;
- an install layout under `ur0:data/livearea-search/` plus a `ur0:tai/config.txt` entry for `*NPXS10015`/SceShell.

The repository includes a container build helper for the configured VitaSDK, ScePaf-RE, and CXML toolchain. It produces the SUPRX, RCO, and install-shaped staging tree locally. The complete flow has been validated on Vita 146; other firmware and hardware variants still require device testing.

## Verification criteria

1. Host tests prove normalization, ranking, deterministic ordering, result limits, URI construction, and rejection of malformed title IDs.
2. Target sources compile with VitaSDK and installed ScePaf-RE stubs.
3. On device, the control appears only on Home, uses the native lower-right magnifier, does not take controller focus, opens the native IME without obscuring it, updates results while typing, restores the full list after Enter, reopens the keyboard when the search field is tapped, and opens the selected title's LiveArea.
4. Forward and reverse scrolling through more results than fit in the surface cache reloads valid artwork without allowing rows to draw outside the dark full or compact result regions.
5. Repeated search/open/close cycles do not leak list rows, stale textures, AppInfo references, surfaces, or event handlers.
